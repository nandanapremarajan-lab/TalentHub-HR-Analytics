# TalentHub — HR Recruitment and Employee Attrition Analytics

**Course:** DBMS for Analytics (25MSDA1S04)  
**Project:** Problem 11 — TalentHub  
**Database:** PostgreSQL + MongoDB  
**Dataset:** IBM HR Analytics Employee Attrition & Performance (Kaggle)

## What this project does
TalentHub models HR departments, job positions, candidates, applications, interviews, employees and employee exits. It analyses recruitment funnel performance, time-to-hire (only for the simulated recruitment records), and employee attrition patterns.

## Dataset and important honesty note
Download the **IBM HR Analytics Employee Attrition & Performance** dataset from:
https://www.kaggle.com/datasets/pavansubhasht/ibm-hr-analytics-attrition-dataset

The original public dataset contains **1,470 fictional employee records and 35 columns**. This project uses a reproducible sample of the first **500 records** for the employee/attrition analysis. It does not claim the fictional records are real employees.

The Kaggle file contains employee/attrition information, not candidate applications, interview stages, hire dates or exit dates. To complete the TalentHub recruitment schema, the project creates clearly labelled **synthetic demonstration records** for candidates, applications and interviews. These are generated for database practice and must not be presented as observed Kaggle data. No monthly hiring/exit trend is inferred from the Kaggle file.

## Setup (Windows)
1. Download the Kaggle CSV above. The expected filename is `WA_Fn-UseC_-HR-Employee-Attrition.csv`.
2. Put that CSV inside the `data` folder.
3. Install PostgreSQL and create a database named `talenthub`.
4. Install MongoDB Community Server, or use an approved MongoDB Atlas account.
5. Open Command Prompt in this folder and run:
   ```bash
   py -m pip install -r requirements.txt
   py run_project.py
   ```
6. The script prepares a 500-row Kaggle employee sample and generates SQL inserts in `sql/data.sql`.
7. Run the SQL files in this order using pgAdmin Query Tool:
   - `sql/schema.sql`
   - `sql/data.sql`
   - `sql/queries.sql`
8. Edit the database settings at the top of `notebooks/TalentHub_Analysis.ipynb` (or use environment variables), then run all notebook cells.
9. For MongoDB, run:
   ```bash
   py mongodb/mongodb_demo.py
   ```

## PostgreSQL connection
Set environment variables before running the notebook/script, or edit the defaults:
- `PGHOST` (default `localhost`)
- `PGPORT` (default `5432`)
- `PGDATABASE` (default `talenthub`)
- `PGUSER` (default `postgres`)
- `PGPASSWORD` (your local PostgreSQL password)

## Required deliverables covered
- 3NF relational design with 7 related tables and PK/FK/check/unique constraints
- SQL DDL and DML
- Trigger to log application stage changes
- View for HR attrition summary
- Analytical SQL queries with JOIN, GROUP BY, HAVING and subquery
- Python DB-API (psycopg2), pandas analysis and matplotlib charts
- MongoDB résumé documents, CRUD, indexes and two aggregation pipelines
- Short SQL vs NoSQL comparison

## Data model limitation
The Kaggle dataset has no application, interview, joining-date or exit-date fields. Recruitment funnel data is therefore simulated. The Kaggle employee sample is used for employee demographics, job attributes, satisfaction and the `Attrition` outcome. For exits, only the Kaggle `Attrition = Yes` label is represented; the project does not invent an exit date.

## Suggested project conclusion
TalentHub demonstrates how a normalized relational database can support HR reporting while MongoDB can store flexible résumé information. Employee attrition can be examined by department, job role, overtime, satisfaction and tenure. Recruitment funnel metrics are demonstrated using separately identified synthetic application/interview records. Results are educational and should not be used to make decisions about real employees or candidates.
